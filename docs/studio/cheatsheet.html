Player Prompt Cheat sheet Michael Gogins

Cheat sheet

Create and revise pieces in Cursor. The Player only plays them.

Say the same sentences in Cursor chat on the computer and at cursor.com/agents on the phone, on this repository. Begin with Follow studio-tools/AGENT_INSTRUCTIONS.md unless that file is already the Cursor rule.

New piece

Follow studio-tools/AGENT_INSTRUCTIONS.md. Create a composition named NAME: …. Render, accept, publish, and push to master.

Next version

Follow studio-tools/AGENT_INSTRUCTIONS.md. Revise NAME: …. Render, accept, publish, and push to master.

Create a composition named NAME runs 'studio new NAME'. That command stops if the name already exists. Revise NAME runs 'studio stage NAME'. That command stops if the name does not exist. The name is the context.

On the computer the agent pushes from the local checkout. On the phone the cloud agent clones the repository, runs the same commands, and pushes to master. The Player plays the version after GitHub Pages rebuilds.

Speak

Click the microphone in the Cursor chat, or press Cmd+Shift+Space. Speak the sentence, read the text, then send it. In the Agents window, hold Ctrl+M while you talk. On the phone, use the microphone in the prompt box at cursor.com/agents.

The Player header link Prompt opens the Cursor app on the computer with Follow studio-tools/AGENT_INSTRUCTIONS.md. already in the chat. Finish the sentence and send it. On a phone, Prompt opens cursor.com/agents. The Cursor app opens that address when the app is installed.

Listen

The Player performs the published .csd. Play MIDI previews the General MIDI file in the browser. On the website, Open MIDI downloads that file. On this Mac, studio serve, then 127.0.0.1:8000/studio/, and Open MIDI shows the file in its folder.

Commands

From the repository root, with studio-tools/bin on PATH. Replace NAME with the piece's name: studio new MyName.

studio new and studio stage print a staging directory. Save it for the next commands: S=$(studio new MyName), then studio prompt "$S" --file request.txt.

accept refuses a staging area that has not rendered successfully. publish never writes soundfiles. discard does not touch the current version. studio COMMAND --help prints the flags. Useful flags: render --wav FILE (a soundfile outside the repository), publish --dry-run, recover --rollback.
