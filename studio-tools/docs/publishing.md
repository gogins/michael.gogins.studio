# Publishing

The archive, `music/ai-compositions/`, is private working material until
something is published. Publishing copies selected files to
`docs/compositions/`, at the same relative paths, and regenerates
`docs/compositions/catalog.json`. The viewer in `docs/studio/` shows what
the catalog lists.

Publishing never writes to the archive. On this repository, whatever is in
`docs/` on the deployed branch is public on the website, so publishing and
then deploying is what makes a composition public. Publishing on a feature
branch is a local matter until that branch is deployed.

## Commands

```sh
studio publish nu --dry-run            # show what would be copied; write nothing
studio publish nu                      # all versions, default kinds
studio publish nu --versions current   # only the current version
studio publish nu --versions current,2 # the current version and version 2
studio publish nu --kinds csd,audio    # only the .csd and the listening copy
studio publish nu xi                   # several compositions
studio unpublish nu --versions 1       # remove version 1 from the published files
studio unpublish nu                    # remove the whole composition from the published files
studio catalog                         # regenerate catalog.json only
```

### Selection

- **Compositions**: named on the command line. Nothing is published that
  was not named.
- **Versions**: `--versions all` (the default), or a list of `current` and
  version numbers.
- **Kinds**: `--kinds`, a list from

  | Kind | Files | Default |
  | --- | --- | --- |
  | `csd` | `<name>.csd` | yes |
  | `prompts` | `<name>-prompt-NNN.md` | yes |
  | `code` | `code/...` | yes |
  | `manifest` | `<name>-manifest.json` | yes |
  | `audio` | listening copies: MP3, Opus, Ogg, M4A | yes |
  | `derived` | MIDI, MusicXML, PDF, images and other outputs | yes |
  | `master` | FLAC, WAV, AIFF masters | no |
  | `logs` | render and generation logs | no |

  Masters are large and logs describe the machine, so both are published
  only when asked for (`--kinds all`, or by name).

Selections add up: publishing `--versions current` today and
`--versions 1` tomorrow leaves both published. Use `unpublish` to
withdraw something.

## Safeguards

The tool makes a complete plan first and writes nothing if any part of it
is refused.

- **The archive is checked first.** A composition that does not pass
  `studio verify`, or has an interrupted version operation, is not
  published.
- **Unchanged files are skipped.** A second run copies nothing and leaves
  the catalog and its timestamp alone.
- **Conflicts stop the run.** `docs/compositions/.publish-state.json`
  records the hash of every file the tool has published. A destination
  file that the tool did not publish, or that was changed since it did,
  is a conflict. The run stops with nothing written; `--force` overwrites.
- **Nothing is deleted by accident.** If a published file's source has left
  the archive selection (for instance a `code/` file that a later version
  no longer has), the run stops and lists the stale files. `--prune`
  removes them, and only if they are still exactly as published;
  otherwise that is a conflict too. `unpublish` applies the same rule.
- **Paths stay inside `docs/compositions/`.** Every destination is checked:
  no `..`, no absolute paths, no hidden files, no symbolic links, and the
  resolved path must lie inside the directory. The state file is checked
  the same way when it is read, so a tampered state file cannot direct a
  deletion elsewhere.
- **Private material stays private.** Only named compositions and the
  selected versions and kinds are copied. Staging directories, locks and
  hidden files are never published. Text files beginning with a `---`
  line are refused, because GitHub Pages would treat them as templates.
- **Dry run.** `--dry-run` prints the plan (`copy`, `update`, `skip`,
  `conflict`, `blocked`, stale entries) and writes nothing.

## The catalog

`catalog.json` is generated by scanning `docs/compositions/`, not the
archive, so it lists exactly what is published. For each composition it
gives the versions, newest first, and for each version the `.csd`, the
prompts, the code, the audio (listening copies before masters), other
derived files, the logs if published, and a summary taken from the
published manifest. All paths are relative to `docs/compositions/`. It is
rewritten only when its content changes.

The text of every published prompt is also embedded in the catalog. GitHub
Pages builds this site with Jekyll, which converts Markdown files into HTML
pages; whether the raw `.md` files remain reachable on the deployed site
has not been verified. The viewer therefore shows and offers prompts for
download from the catalog and does not depend on fetching the `.md` files.

## Optional artifacts

A version may be published without audio, without code or without its
manifest. The catalog simply omits what is absent and the viewer says so
("No audio was published for this version", and so on). MIDI, MusicXML
and PDF files in `outputs/` are listed in the viewer's Files tab when
published.

## Public exposure

`studio publish` only writes into the working tree. A composition becomes
public when the commit containing `docs/compositions/` reaches the branch
that GitHub Pages deploys. See [deployment.md](deployment.md). Do not push
or merge published material without the composer's approval.
